## 当前判断

项目已经是功能较完整的内测原型，不是只有界面的空壳。Tauri IPC 与 Rust engine 分层清楚，浏览器预览有 mock，已有原版安装、Java、账号、加载器、资源中心、整合包、崩溃分析和三套布局。

## 本轮完成

- 为本地仓库关联 `origin`：`https://github.com/MRTangwin8/TheGodBBSLauncher.git`。只读检查确认当前凭据可以访问空仓库；维护者已授权将已有历史和本轮修改首次提交、推送至该私有仓库。
- 微软登录保留前端需要的用户验证码，但不再序列化用于后端轮询的 `device_code`。
- 游戏启动命令、stdout/stderr、崩溃诊断的展示字段统一脱敏：既屏蔽当前会话令牌，也识别常见凭据字段、Authorization 和旧版 session。
- 游戏退出后的日志读取任务超时会被终止，避免子进程占着管道时一直遗留后台任务。
- 断点续传核对 `206` 的 `Content-Range`、起点、终点和总大小。错误范围清除临时文件后重试；服务器忽略 Range 时从头下载。
- SHA1 与已知大小同时校验；快速补全遇到没有已知大小的文件仍校验哈希；目录不再被当成下载完成的文件。
- 补充本地 HTTP 模拟测试及凭据脱敏回归测试，不依赖 Mojang 或镜像联网。
- GitHub 构建新增手动触发、只读仓库权限、重复运行取消、锁定 Rust 依赖和产物缺失检查。安装包产物保留 14 天，不自动发布 Release。
- 忽略本地游戏目录、账号文件、环境变量文件和常见私钥文件，减少首次上传夹带敏感数据的风险。

这里的日志脱敏只作用于启动器输出给界面的内容和诊断结果，不会改写 Minecraft 或模组自己生成的磁盘日志。向外分享原始日志前仍应人工检查。

## 后续优先级

### P1：内测可靠性与安全

1. 补齐真实启动验收矩阵：原版 1.8.9 / 1.12.2 / 1.20.1、所选新版本，以及 Fabric / Quilt / Forge / NeoForge。覆盖启动失败、手动结束、崩溃诊断和再次启动。
2. 修复前端启动登记与退出事件的竞态：`src/stores/game.ts` 暂存了提前到达的日志，但提前到达的退出事件目前可能丢失。
3. 统一外部元数据和整合包的路径安全边界。现有 `safe_rel` 能拦截常见 `..`，但还需要覆盖库路径、继承 ID、Windows 保留名称和已有符号链接 / junction。未完成前不要承诺任意第三方整合包都能安全导入。
4. 加固系统钥匙串不可用时的回退。`engine/auth/vault.rs` 目前会使用配置目录里的密钥文件，文件写入失败被忽略，也没有专门限制 Unix 文件权限；应显式处理错误与告警，并验证钥匙串恢复后的密钥选择。
5. 给安装 / 导入增加取消、任务互斥与恢复策略，避免多个任务同时操作同一缓存文件或重复创建实例。
6. 验证 Apple Silicon 旧版支持。当前 Java 架构选择不等于已经具备旧 LWJGL natives 替换方案。

### P2：发布与长期维护

1. 首次推送后观察三平台 CI，修复平台专属问题，下载并实际安装生成的安装包。
2. 微软公共客户端 ID 归属与 API 权限已由维护者确认；继续完成授权、续期、取消和错误提示的真实验收。
3. 选定稳定的内测版本号，补充变更记录和许可证文件；对外发布前确定签名方案。
4. 自动更新采用签名校验；不能把访问私有 GitHub 仓库的个人令牌放进客户端。更新源与制品分发方式需要维护者选择。
5. 在可靠性验收后再扩展实例设置、存档管理、服务器列表、启动前后钩子和插件系统。导入第三方整合包不能默认授权执行脚本。
