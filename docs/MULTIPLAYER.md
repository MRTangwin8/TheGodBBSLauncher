# 联机功能设计：接入陶瓦联机（Terracotta）

状态：**第一期已实现**（2026-11-04，陶瓦 v0.4.2）。实现时发现的情况记在第 11 节。

## 1. 目标

让玩家在启动器里**输入一个房间码就能和朋友联机**：
- 不需要公网 IP、端口映射、注册账号，也不需要管理员权限；
- 和其他接入了陶瓦（或实现了 Scaffolding 协议）的客户端互通，对方用别的工具开的房间，我们也能进。

不做的事：
- 不自己写组网和打洞，全部交给陶瓦（它底层是 EasyTier）；
- 不改陶瓦的代码，不链接它的库。

## 2. 陶瓦是怎么工作的（摘要）

| 环节 | 做法 |
|---|---|
| 房间码 | `U/NNNN-NNNN-SSSS-SSSS`：前半段拼成 EasyTier 网络名 `scaffolding-mc-NNNN-NNNN`，后半段是网络密钥；字符按 0-9、A-H、J-N、P-Z 映射成 0~33，按小端读出的整数能被 7 整除（用来校验输错） |
| 组网 | EasyTier 加 `--no-tun`（不建虚拟网卡，不要管理员权限）和 `--p2p-only`（公共节点只做撮合，不中转游戏流量） |
| 房主 | 扫描本机「对局域网开放」的 MC 端口；虚拟 IP 固定为 `10.144.144.1`，主机名 `scaffolding-mc-server-<控制端口>`；白名单只放行 MC 端口和控制端口 |
| 房客 | 用 EasyTier 端口转发把本机端口映射到房主的 MC 端口（尽量用同一个端口号，语音聊天模组要用），再往 `224.0.2.60:4445` 发局域网广播，游戏的多人列表里就出现「陶瓦联机大厅」 |
| 控制协议 | Scaffolding（MIT）：TCP 上的小协议，`c:ping`、`c:protocols`、`c:server_port`、`c:player_ping`（5 秒心跳）、`c:player_profiles_list` |
| 对外接口 | 本机 `127.0.0.1` 随机端口上的 HTTP API，没有鉴权，全是 GET |

## 3. 方案选择

**选：打包外部进程，用 HTTP API 控制。**

陶瓦的许可证是 AGPL-3.0，但带两条例外。满足下面两点，我们的代码就不会被 AGPL 覆盖：
1. 使用未经修改的陶瓦二进制，不做静态或动态链接；
2. 通过它的 HTTP API 交互，并且**在界面显眼处标注陶瓦的版权信息**。

不选的方案：自己实现 Scaffolding 协议，再嵌入 EasyTier（LGPL）。这样不依赖陶瓦的二进制，但要自己维护组网参数、打洞、端口转发、局域网广播，工作量大好几倍。等陶瓦方案跑稳了再考虑。

### 自己实现的评估（2026-11-04）

陶瓦本身的结构：拉起 `easytier-core` 和 `easytier-cli` 两个程序（来自作者 fork 的 EasyTier；fork 只改了一个文件，把几个字段改成公开，给安卓版链接用，桌面版等于官方版），再在外面实现房间码、Scaffolding 控制协议、局域网扫描和广播。自己实现就是**用官方 EasyTier 程序加我们自己写的这一层**，有三种做法：

| | A. 打包陶瓦（上面的方案） | B. 自己实现 + EasyTier 程序 | C. 自己实现 + EasyTier 当 Rust 库 |
|---|---|---|---|
| 后端代码量 | 约 600 行 | 约 1,800 行 | 约 1,800 行，还要适配库接口 |
| 下载体积 | 约 8 MB | 官方压缩包 39 MB（里面两个网页版程序用不上），只取 core + cli 约 27 MB；也可以自己重新打包后放进我们的 Release | 不用下载，但所有人的安装包大约多 15 MB |
| 许可证 | AGPL 例外：界面必须显眼标注 | EasyTier 是 LGPL，作为独立程序运行，只要在「关于」里列出许可证和源码地址 | LGPL 静态链接；我们的源码完全公开（MIT），可以满足重新链接的要求，但要写清楚 |
| 和游戏的结合 | 只能通过它的接口 | 完全自己控制（见下） | 同 B |
| 商店版 | 需要下载外部程序，审核有风险 | 同 A | **不用下载任何程序**，商店版也能用 |
| 维护 | 跟陶瓦升级 | 自己跟 Scaffolding 协议（还在开发中）和 EasyTier 命令行输出格式的变化 | EasyTier 的库接口不稳定（crates.io 上只有 2024 年的 2.0.3，只能用 git 依赖），依赖约 180 个，三平台 CI 和编译时间都会明显增加 |

自己实现的好处（B 和 C 都有）：
- 房主端口直接从游戏日志里读（我们本来就解析 log4j），不用扫描局域网广播；游戏退出就自动关房间。
- 加入成功后可以直接用 `--quickPlayMultiplayer` 启动游戏进服，整个流程在一个页面里完成。
- 不受陶瓦单实例锁的影响，用户同时开着别的陶瓦客户端也不冲突。
- 界面不用显眼标注第三方版权；按 Scaffolding 协议实现，房间码照样和陶瓦互通。
- 可以复用已有代码：`servers.rs` 的 Server List Ping 用来检测服务器是否可达，下载和校验沿用 `zulu.rs` 的做法。

代价：
- 陶瓦踩过的坑要重新踩一遍：语音模组要求端口号一致、IPv6 广播、各平台的网络细节。它有 210 次提交、43 个版本。
- **不能复制陶瓦的代码**：它是 AGPL，我们是 MIT。只能按 Scaffolding 协议文档（MIT）和 EasyTier 的命令行文档自己写。

结论：
- **想尽快有联机** → A，一两周能做完，最成熟。
- **联机要做成主打功能、和启动流程打通** → B。工作量大约是 A 的 2~3 倍（后端），换来完整的控制权，也不用在界面上标注第三方。EasyTier 那一层要封装好，以后可以换成 C。
- **商店版必须有联机** → 只能 C，或者把程序打进 MSIX 再去试审核；建议等 B 跑稳了再说。

**决定（2026-11-04）：先做 A。** 以后换成 B / C 时：
- 停用陶瓦后，它的 AGPL 对我们就没有约束了；用 A 的这段时间，靠例外条款，我们的代码也从来不受 AGPL 约束。已经发布的旧版本照常保留版权标注。
- 唯一要守的是：B / C 的代码**只能按 Scaffolding 协议文档（MIT）和 EasyTier 文档写，不抄、不改写陶瓦的源码**。协议和思路不受版权保护，具体代码受。实现 B 时在提交说明里写清楚参照的是协议文档。

## 4. 获取陶瓦二进制

做法和下载 Java（`engine/java/zulu.rs`）一样：**按需下载，安装包里不带**。

- 来源：GitHub Releases `burningtnt/Terracotta`。国内网络不好时用 Gitee 镜像，同名文件；镜像的下载地址格式实现时要实测。
- **版本和 SHA256 写死在代码里**，不读接口返回的校验值。升级陶瓦要改代码，这是故意的：外部二进制会在用户机器上运行，必须是我们看过的版本。
- 每个平台用的文件（以 v0.4.2 为例）：

| 平台 | 附件 | 解出来要用的文件 |
|---|---|---|
| Windows x64 / arm64 | `terracotta-0.4.2-windows-<arch>-pkg.tar.gz` | `terracotta-0.4.2-windows-<arch>.exe` 和 `VCRUNTIME140.DLL` |
| macOS arm64 / x64 | `terracotta-0.4.2-macos-<arch>-pkg.tar.gz` | `terracotta-0.4.2-macos-<arch>`（裸二进制；同包里的 `.pkg` 会装开机自启，**不用**） |
| Linux x64 / arm64 | `terracotta-0.4.2-linux-<arch>-pkg.tar.gz` | `terracotta-0.4.2-linux-<arch>` |

- 放到 `AppState::runtime_dir()/terracotta/<版本>/`。商店版的 runtime 在用户主目录下，不进 AppData（理由见 AGENTS.md「微软商店版」）。
- 解压用现有的 `flate2` + `tar`：只取上表列出的文件名，忽略其他条目，不信任包里的路径。Unix 上加可执行权限。
- 通过 HTTP 客户端下载的文件没有 macOS 的「隔离」属性，Gatekeeper 不会拦截。实现时要在真机上确认一次。

## 5. 后端设计

### 模块

```
engine/multiplayer/
  mod.rs        对外类型：MpState、Profile、Difficulty
  release.rs    写死的版本表（平台 → 文件名、SHA256），下载、校验、解压
  process.rs    启动 / 结束陶瓦进程，拿到 HTTP 端口
  api.rs        调用 HTTP API，解析 /state
  room.rs       房间码格式校验（和陶瓦相同的规则，含能被 7 整除的检查）
commands/multiplayer.rs
```

### 启动进程
- 命令：`terracotta --hmcl <端口文件>`。端口文件放在数据目录下的临时位置，写入格式是 `{"port": N}`（陶瓦先写 `.tmp` 再改名，所以读到的一定是完整内容）。
- 等端口文件出现，最多 10 秒，超时就报错并结束子进程。
- Windows 上 `--hmcl` 进程只负责引导，会 fork 出真正的工作进程。所以**结束陶瓦要调 `GET /panic?peaceful=true`**，不能只杀我们拉起的那个子进程。
- 启动器退出时（`lib.rs` 的 `RunEvent::Exit`）调一次 `/panic?peaceful=true`。
- **待验证**：陶瓦用锁文件 `terracotta.lock` 保证单实例，如果已经有一个陶瓦在跑（例如用户同时开着别的工具），新进程会「附属」到已有实例。这时我们退出时不该把别人的实例关掉。实现时要实测附属进程的行为，再决定怎么判断。

### 状态
- 后端每 500 ms 轮询 `GET /state`（联机页不在前台时降到 15 秒），只在 `index` 变大时向前端推送 `multiplayer-state` 事件。这和现有的 `install-progress`、`game-log` 用法一致，前端不需要自己轮询。
- 连续 5 次请求失败，就认为陶瓦已经退出，推送一个「联机服务已停止」的状态。
- 状态机（陶瓦定义）：`waiting` → 房主 `host-scanning` → `host-starting` → `host-ok`；房客 `guest-connecting` → `guest-starting` → `guest-ok`；任何时候都可能进入 `exception`（type 0~5），要调 `/state/ide` 才能回到 `waiting`。
- serde：`#[serde(tag = "state", rename_all = "kebab-case")]`。没见过的状态解析成 `Unknown`，不报错，以兼容陶瓦以后的版本。

### 命令（参数和返回值用 camelCase）

| 命令 | 作用 |
|---|---|
| `mp_status` | 是否已下载、版本号、进程是否在跑、当前状态 |
| `mp_install` | 下载并校验陶瓦，进度走 `install-progress`（带 `jobId`） |
| `mp_host` | 启动进程（如果还没启动），调 `/state/scanning?player=…` |
| `mp_join` | 先在后端校验房间码，再调 `/state/guesting?room=…&player=…` |
| `mp_leave` | 调 `/state/ide` |
| `mp_stop` | 调 `/panic?peaceful=true` |

- `player` 用当前账号的**角色名**，不传令牌，也不传 UUID（红线 3）。
- URL 参数用 reqwest 的 query 编码拼接，不手拼字符串。
- 陶瓦只写 runtime 目录，不写游戏目录，所以这些命令不需要 `begin_task`。
- 错误用 `Error::coded("mp.xxx", …)`，前端在语言包 `err.mp.*` 里翻译。

### 不可信数据
- `profiles[].name` 是其他玩家填的名字：当纯文本显示，限制长度（例如 32 个字符），不当 HTML 渲染。
- `guest-ok` 的 `url` 只接受 `127.0.0.1` 或 `127.0.0.1:<端口>`，不符合就不显示，也不用它启动游戏。

## 6. 前端设计

### 新页面「联机」
- 加进 `router.ts` 的 `navItems`，图标名用 `link`，`PixelIcon` 和 `ModernIcon` 各画一个原创图标。
- 第一次打开时显示说明，按钮是「启用联机（需要下载约 8 MB）」。点了才下载，不在后台自动下。
- 两个入口：
  - **开房间**：提示「先启动游戏、进入存档，在游戏菜单里点『对局域网开放』」。扫描到之后显示房间码（大字号，带「复制」按钮）和成员列表。
  - **加入房间**：输入框边输入边校验格式。连接中显示 NAT 难度（`EASIEST` … `TOUGH`，翻译成「很容易」到「较难」）；`TOUGH` 时提示可能连不上，建议换个网络或换人开房。成功后显示「在多人游戏里双击『陶瓦联机大厅』」和备用地址。
- `exception` 的 6 种 type 各有一句说明和下一步建议，例如「房主退出了存档，房间已关闭」。
- 页面底部固定显示：**「联机功能由 Terracotta | 陶瓦联机提供，AGPL-3.0 许可」**，带源码链接。设置页「关于」的第三方许可里也要加上。这是许可证例外条款的要求，不能省。

### 和现有功能联动（第二期）
- **加入并启动**：加入成功后、游戏还没运行时，给一个「启动游戏并直接进入」按钮，用现有的 `launch_game` 的 `server` 参数（1.20 起用 `--quickPlayMultiplayer`）。
- **开房间**：游戏没在运行时，「开房间」先引导用户启动游戏。

### 其他同步
- `api/types.ts`、`api/index.ts`、`api/mock.ts`：mock 里写一个假的状态机（隔几秒自动推进到 `host-ok` / `guest-ok`），这样浏览器预览能走完整个流程。
- 三种语言包加 `mp.*` 和 `err.mp.*`。
- 三种布局 × 深浅色都看一遍。

## 7. 商店版

**第一期在商店版里不开放联机**（`edition::STORE` 时隐藏页面，后端命令直接拒绝）。原因：
- 商店政策不允许应用下载并运行会改变应用功能的代码（10.2.2）。下载 Java 是运行游戏本身，而陶瓦是一个新的网络服务，审核时说不清楚；
- 不签名的 exe 在 MSIX 环境里，首次运行还会弹防火墙提示，体验也要单独验证。

如果以后要在商店版开放，可以考虑把陶瓦二进制直接打进 MSIX 包里，再提交审核看结果。

## 8. 隐私与安全

- 联机时，对方能看到你的公网 IP（P2P 直连本来就这样），EasyTier 公共节点也能看到你的 IP 和网络名。陶瓦还会把设备标识（`machine_id`）发给房间里的其他人。这些要写进 `docs/PRIVACY.md`，并在第一次启用联机时告诉用户。
- 陶瓦的 HTTP API 没有鉴权，本机任何进程都能调用。我们只连 `127.0.0.1`，不暴露到外部。
- 房主的白名单只放行 MC 端口和控制端口，房客访问不到房主机器上的其他服务（这是陶瓦自己的设置）。
- Windows 第一次运行时可能弹防火墙提示，界面里要提前说明「请允许访问网络」。

## 10. 实现前要实测的问题

1. 已有陶瓦实例在跑时，`--hmcl` 附属进程的行为：会不会写端口文件，我们退出时怎么避免关掉别人的实例。
2. Windows 防火墙提示什么时候弹、点「取消」后还能不能联机（P2P 打洞可能仍然可用）。
3. macOS 上通过 HTTP 下载的裸二进制能否直接运行，arm64 和 x64 都要试。
4. Gitee 镜像的下载地址和 GitHub 是否同名。
5. 离线账号开房、正版账号加入（以及反过来），能不能进。陶瓦文档说从大厅加入时游戏会忽略正版验证，要实际试一遍。
6. 和其他陶瓦客户端互通：对方开房、我们加入，以及反过来。

## 11. 第一期实现记录（2026-11-04）

- 代码：`engine/multiplayer/`（`release` / `process` / `api` / `room`）、`commands/multiplayer.rs`、`views/MultiplayerView.vue`，冒烟测试 `examples/multiplayer.rs`。
- **macOS 暂不支持**：陶瓦在 macOS 上不自己当服务端，而是用 `launchctl` 拉起安装包装进 `/Library/LaunchAgents` 的后台服务；只有裸程序起不来。要支持得让用户先装它的 `.pkg`，或者等改成方案 B。
- **判断实例归属**：Windows 上陶瓦并不独占锁文件，靠「打不开锁文件」判断不可靠。改成读锁文件里的端口（2 字节大端）再问 `/meta`，答得上来就是已有实例。已实测：没有实例时 `owned = true`；先手动启动一个陶瓦，再用启动器启动时 `owned = false`、拿到的是已有实例的端口。
- 陶瓦全局只有一个状态机：别的程序用同一个实例开的房间，也会显示在我们的联机页里。
- 在 Windows 上实测通过：从 GitHub 下载并校验、解压、启动、拿端口、`/meta`、开房间进入 `host-scanning`、回到待机、`/panic` 退出后没有残留进程。Gitee 镜像地址（`/releases/download/v<版本>/<文件名>`）能正常跳转下载。
- 还没验证：第 10 节的 2、5、6（防火墙、正版 / 离线互通、和其他陶瓦客户端互通），以及 Linux 真机。
- **真机测试（2026-11-05，日本网络）**：Windows 用启动器开房、Mac 用 HMCL 加入。开房、扫描端口（49838）、对方进房都正常，但两台之间的 P2P 直连延迟 100~300 ms、丢包 12%~30%，心跳反复超时，游戏一直卡在「正在连接」。换手机热点、关掉 Tailscale 也一样；两边都用 HMCL 也连不上，HMCL 界面上提示联机只面向中国大陆用户。内置的 4 个公共节点在这里只有一个能用。结论：不是启动器的问题，是陶瓦在中国大陆以外的网络表现差。联机页已经加上地区提示。
